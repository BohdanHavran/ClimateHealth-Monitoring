# GitHub: локальний стан і наступний push

23.11.2026. Єдиний remote `origin`: `git@github.com:BohdanHavran/ClimateHealth-Monitoring.git`. Git ініціалізовано лише в основній програмній директорії, `HEAD` → `main`. Нового GitHub-репозиторію не створено. Нормальний SSH без явного ключа підтвердив `BohdanHavran`; `git ls-remote origin` завершився з кодом 0 і порожнім списком refs. Код не відправлено.

Початковий SSH-запит відхилено publickey, повторний звичайний запит після повідомлення користувача спрацював. Приватні ключі не читалися й не копіювалися, SSH config/known_hosts не переписувалися. Спроба GitHub connector дала `not connected`, тому стан перевірено Git/SSH. Глобальні Git settings не змінювалися; через різного власника файлів у середовищі інструмента використовується тільки разовий `git -c safe.directory=<саме ця директорія>`.

## Перед комітом

`scripts/scan_secrets.py` сканує лише Git-кандидатів або точний index; значення знахідок не друкує. Локальний `--known-secret-env` перевіряє повні credential values з наданого `.env`, не довільні слова у назвах змінних. Цей шлях не передається CI. Відсутність евристичних знахідок не доводить повної відсутності секретів. Перевірені синтетичні фікстури мають точкові allowlist-коментарі.

До початкового коміту належать вихідний код, React source і package-lock, тести, конфігурації без credentials, SQL baseline та технічна документація. Виключені `.env`, `.venv`, `.secrets`, CSV невідомого походження, `course.zip`, локальні screenshots і метадані MySQL, generated graph HTML/JSON/cache, node_modules/dist, state/plan/real tfvars, ключі та backups. Архів із первинним API-ключем лишається поза публікацією. Ключ у провайдера потрібно відкликати/замінити; перевірка його чинності не проводилася.

Ім’я/email автора Git не налаштовані, користувачу поставлено окреме запитання. Не підставляти вигадані реквізити. Фактичний стан коміту та index зафіксований у `PHASE2_REPORT.md`; remote не змінюється до окремого дозволу на перший push. Якщо автор не наданий, дозволено підготувати index, але коміт не заявляти як створений.

## Після автора й окремого дозволу

Налаштувати ім’я/email лише в local Git config → перевірити staged files/secrets → створити локальний коміт → показати hash/status → отримати окреме підтвердження на push. Безпосередньо перед push повторно прочитати refs. Якщо remote отримав коміти, спочатку fetch і безпечне узгодження історії, без force або видалення refs. Після дозволеного push перевірити реальні Actions. Наявні workflow ще не є доказом успішного remote CI.
