# ADR 0004: AWS infrastructure and credit budget

Дата: 24.11.2026. **State/compute workflow замінено [ADR 0005](0005-ecs-cloudfront-hcp-terraform.md); AWS як платформа зберігається. Нижче історичне рішення.** Статус: **AWS прийнято користувачем; конкретний регіон, розміри та запуск запропоновані, не погоджені**.

## Контекст
Проєкт «Диплом» розвиває систему ClimateHealth, репозиторій ClimateHealth-Monitoring. Підтверджений кредитний бюджет — $100; додаткові кредити, пільгові години та GPU не враховуються. Наявний застосунок, MySQL, контракти, дизайн і 27 правил HRI зберігаються. Хмарного розгортання немає.

## Рішення
AWS — єдина цільова хмарна платформа. EC2 для застосунку, окремий приватний EC2 для CPU inference за потреби; MySQL на EC2 або RDS for MySQL. Для початкової демонстрації запропоновано один EC2 з окремими Compose-сервісами й без публічних портів MySQL/ML. Два EC2 — ціль розділення компонентів, а не обов'язкова мінімальна конфігурація. Усім сценаріям потрібен окремий дозвіл на створення ресурсів.

Terraform використовує hashicorp/aws, S3 state з native lockfile, окремі dev/production roots і федеративний доступ. GitHub OIDC, ECR, захищені environments та immutable image/model manifests замінюють довгострокові ключі. Без NAT, ALB та платних interface endpoints у базовому кошторисі. Приватний AI отримує підписані OCI-архіви/моделі через S3 gateway endpoint; прямий ECR pull не вважається доступним через один S3 endpoint.

## Альтернативи
1. Один EC2: дешевше й простіше зупиняти; спільна відмова й конкуренція RAM. Рекомендовано як демонстраційний старт після вимірювання пам'яті.
2. Два EC2 + MySQL на application EC2: ізолює inference, але backup/PITR/патчі БД виконує оператор; це не HA.
3. Два EC2 + RDS MySQL Single-AZ: керовані backup/patching і менше навантаження на app; додатковий сервіс, ліміт RAM, storage та потенційні CPU/Extended Support платежі. Single-AZ не є високодоступною production-конфігурацією.

## Наслідки
- Збережено Flask, React/TypeScript/Vite, MySQL, FastAPI/PyTorch, Docker/Compose, Terraform і GitHub Actions; Kubernetes/EKS/Helm виключені.
- Регіон для кошторису us-east-1; реальні медичні дані там не розміщувати без перевірки вимог територіальності й законних підстав.
- Пропонується MySQL 8.4 LTS для майбутнього RDS після compatibility tests; локальну 8.0.40 не оновлюємо. RDS MySQL 8.0 вже потребує Extended Support, не входить до базової оцінки.
- Бюджетні сповіщення не обмежують рахунок. Потрібні регулярний кредитний ledger, строки зупинки, обмеження IAM і окремий контроль залишкових дисків/адрес/копій.
- Історичний Terraform root збережено байт у байт, не є ціллю CI або запуску. State іншої платформи не переносять на AWS через rename або повторне використання key.
