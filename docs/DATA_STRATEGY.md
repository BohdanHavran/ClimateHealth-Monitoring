# Стратегія даних

## Оновлення фази 3

Координатний Open-Meteo інтегровано й перевірено реальними HTTP/browser запитами, зі source/time/units/quality та attribution. Це модельні погодні значення, не станційні вимірювання. CDC NHSN metadata/license/coverage перевірено публічним API, але медичні raw rows і повна training-вибірка не завантажені. Докладні джерела, права, географія, availability gate й кандидат задачі — `ML_DATA_PROTOCOL.md`; докази — `reports/phase3-public-sources.json`. Нижче збережено первинне обґрунтування, його ранній статус «інтеграцію не реалізовано» більше не стосується координатного Open-Meteo.

Дата перевірки джерел: 23.11.2026. Статус: **досліджено / часткові локальні перевірки виконано**, інтеграцію джерел не реалізовано. Основна система: `Диплом 2.0`. HRI є умовним результатом нечітких правил, не медичною міткою чи ймовірністю захворювання. Прогнозна асоціація не доводить причинного впливу.

## Фактичний стан

Локальний `climate_change_dataset.csv` має 53 записи × 20 полів, 94 порожні клітинки, дев'ять текстових `NAN` та сім `Unknown`; медичної цільової змінної серед наявних заголовків немає. SHA-256 `362b9da9b19a729f68d60d06f0c9fa4a16e4b1b6951212d3539a48bb420b8ffe`. Його походження, ліцензію, одиниці частини показників, репрезентативність і право повторного використання не підтверджено. Роки 2020–2024 не доводять безперервності ряду; це помісячні записи. Деякі координати неповні чи некоректні; 42 повні пари повторюють координати 40.7128, −74.006. Набір не демонструє українського охоплення.

Температурні порушення рахуються трьома різними методами: **24** рядки з порушенням Tmin ≤ Tavg або Tavg ≤ Tmax для наявних пар; **27** — коли додатково перевіряється Tmin ≤ Tmax без середнього; **21 із 32** повних числових трійок порушують порядок. У файлі є 99999, зокрема в широті, та текстові пропуски; без документації не можна вважати усі такі числа кодами пропуску. Повних дублікатів 0.

`app.py` читає CSV, але `climat.py` використовує MySQL `climate_data`. Автоматичного імпорту саме цього CSV до MySQL не виявлено. Доступу до фактичної MySQL і її вмісту в цій перевірці не підтверджено; реальний обсяг, склад, права та дані про здоров'я в ній **невідомі**. Глобальна медіана та `bfill` в табличному інтерфейсі не підходять без змін до часового навчання: можливе використання майбутньої інформації.

Відтворити локальний профіль (Python 3.9+):

```powershell
python scripts/profile_dataset.py
python -m unittest discover -s tests -p test_data_quality.py -v
```

Скрипт працює лише на читання, не переписує таблицю і виводить SHA-256, заголовки, порожні й текстові маркери, географічні діапазони та визначені температурні перевірки. Він не є автоматичним визначенням походження чи медичної цілі. `climate_data_quality.py` — незалежний набір перевірок скінченності, діапазону й часової доступності; це не повна валідація постачальника, не імпорт і не інтеграція у Flask.

## Контракти та якість

Для кожного джерела — паспорт: власник, походження, URL/версія, ліцензія й умови, одиниці, охоплення, період, частота, зона часу, схема, частка пропусків, аномалій, затримка і ревізії. Сирий знімок зберігати незмінним окремо від похідних даних; фіксувати SHA-256, час отримання і версію перетворення. Ліцензії й персональні дані оцінюються для конкретного набору до збирання або публікації.

Пропоновані поля для майбутніх MySQL-таблиць: `region_id`, `event_time`, `available_at`, `ingested_at`, `source_id`, `version`, `value`, `unit`, `quality_status`, `revision`; для медичного агрегату — категорія, кількість або rate та повнота. Схему не змінено. Часові позначки — із часовим поясом, нормалізація у UTC з окремим локальним днем; зони й межі регіонів версіонуються. Для кожного запиту `available_at <= issue_time`; дата спостереження сама по собі не доводить доступності.

До моделювання: перевірити унікальність ключів, часові інтервали, пропуски, дублювання, нетипові маркери, географічні межі, NaN/±Inf, сталі одиниці, `min ≤ avg ≤ max` і межі фактичної наявності. Сирі значення і прапорці якості зберігати окремо від результату очищення. Не підставляти нуль замість пропущеної медичної цілі. Не використовувати майбутні дані або ретроспективний реаналіз як архів виданих прогнозів погоди.

Підготовлені файли не є підтвердженим медичним набором. Перший data gate: письмово погодити ціль, регіон, горизонт, категорію, джерело і законні умови; отримати метадані та контрольний знімок; перевірити достатність часових спостережень і затримку публікації. До проходження gate медичний прогноз недоступний.
